# ふたりの予定

2人で空いている日を共有する、スマホ向けのシンプルなスケジュール調整アプリ。LINEで招待リンクを送り、LINE内ブラウザでそのまま使えます。

1. 1人がカレンダーを作る → 2. 招待リンクをLINEで送る → 3. 相手が名前を入れて参加 → 4. それぞれ空いている日（土日・祝日は昼/夜）をタップ → 5. 2人が一致した日・時間帯が緑になる

## 技術構成

| 層 | 採用 | 理由 |
| --- | --- | --- |
| フロント | 素の HTML/CSS/JS（ビルドなし）`public/` | LINE内ブラウザで壊れにくい。依存なし |
| API | Vercel Serverless Functions `api/*.js` | 常駐サーバー不要 |
| DB | Neon Postgres | 共有データの唯一の保存先（端末内には識別用トークンしか持たない） |
| 同期 | 3秒ごとの差分ポーリング + 画面復帰・回線復帰時の即時取得 | Vercel の関数は WebSocket を保持できない。外部の有料リアルタイム基盤を足さずに安定して動くため |

「リアルタイム」は WebSocket ではなく**約3秒以内のポーリング**です。DBには変更のたびに増える版番号(`rev`)があり、変化が無ければ本体を返さず軽く済みます。

## 仕組み（要点）

- **空き状況は項目ごとに独立保存**: `availability(カレンダー, 参加者, 日付, 時間帯)` の1行が1つの「空き」。選択=行の追加、解除=行の削除。変更した項目の行だけを更新するので、2人が同時に操作しても互いを上書きしません。
- **時間帯**: 平日は `all`（その日）、土日・祝日は `noon`（昼）/`night`（夜）。種別に合わない組み合わせはサーバーが拒否します。一致判定は同じ時間帯どうしだけ（昼と夜は一致にならない）。
- **日本の祝日**: `public/holidays.js` が法律の規則（ハッピーマンデー、春分/秋分、振替休日、国民の休日）から毎年計算するので、年が変わっても更新不要（春分・秋分の近似式は2099年まで有効）。日付は常に日本時間の `YYYY-MM-DD` 文字列で扱い、端末のタイムゾーンに依存しません。
- **保存の信頼性**: 変更は1リクエストずつ順番に送信。同じ項目は最後の指定が勝つ。失敗した変更は「保存済み」と表示せず、赤枠＋「保存できていません」で保持し、自動再試行（指数バックオフ）。再接続時は最新の共有データを全件取り直します。
- **アクセス制御（サーバー側）**:
  - 参加者の識別は、参加時にサーバーが発行する256bitのランダムトークン（DBにはSHA-256のみ保存）。全APIが `Authorization: Bearer` を検証し、変更できるのはそのトークンの持ち主の行だけ（APIに「誰の」を指定する引数がありません）。
  - 1カレンダー2人までは、DBの一意制約 `(calendar_id, slot)` が保証（同時参加でも1人だけ成功）。
  - 招待リンクを「開いただけ」では何も変わりません（参加は名前入力後の明示操作）。招待コードでは既存参加者になれず、データも読めません。2人揃ったあとは招待コードは無効です。
  - 存在しないカレンダー・トークン違い・他人のカレンダーは、すべて同じ 403 を返します（存在の有無も分かりません）。
- LINEアカウントとの連携はありません（リンクを共有するだけ）。

## 時間帯パターン（バイトの時間などに合わせた「何時まで／何時から空いている」）

- 平日と、土日・祝日の「夜」は、タップするたびに **未選択 → 終日 → 自分のパターン（最大3つ）→ 未選択** と切り替わります。昼は 選択 ⇄ 解除 のみです。
- パターンの初期値は、平日が「9時まで」「18時まで」「21時から」、夜が「21時まで」「23時まで」。設定画面で好きな時刻・種類（まで／から／使わない）に変えられます（本人のDB上の設定で、別の端末でも同じ）。
- セルには範囲を小さく表示します（`〜18`、`21〜`）。一致したセルには **2人の範囲の重なり** を出します（例: 自分が「18時まで」・相手が「終日」→「〜18」、自分「18時まで」・相手「9時まで」→「〜9」）。
- 「18時まで」と「21時から」のように重ならない場合は一致にせず、黄色の「時間がすれ違い」（●◆）で表示します。
- 保存形式: `availability.code`（`F`=終日 / `U18`=18時まで / `S21`=21時から）。既存の行は `F` になります。API は `set` の変更に `code` を指定（`''`=解除）。旧形式の `on: true/false` も受け付けます。

## 使い方のコツ

- **ふだんは閲覧専用**（スクロール中の誤タップ防止）。変更するときは画面下の「✏ 編集する」を押し、終わったら「✓ 編集を終わる」。編集中だけ、タップ・曜日まとめ・なぞり選択が効きます（カレンダーが青い枠で囲まれます）。

- 日付/昼・夜をタップで選択・解除。**曜日（月〜日）をタップ**でその月の同じ曜日をまとめて選択、**横になぞる**と連続選択。
- 別のブラウザ（LINE内→Safariなど）で同じ「あなた」として開くには、設定の「自分用の復元リンク」を使います（**相手には送らない**）。LINE内ブラウザの保存領域は外のブラウザと別です。

## セットアップ（自分でデプロイする場合）

1. **Neon**: プロジェクトを作成し、接続文字列（pooled）を取得
   ```bash
   npx neonctl auth
   npx neonctl projects create --name futari-akibi
   npx neonctl connection-string --project-id <id> --pooled
   ```
2. **ローカル**: `.env` に `DATABASE_URL=<接続文字列>` を書く（コミットしない）→ テーブル作成と起動
   ```bash
   npm install
   npm run migrate
   npm run dev      # http://localhost:3000
   ```
3. **Vercel**: GitHub に push → Vercel でインポート（Framework: Other。`vercel.json` が出力先を設定済み）。環境変数 `DATABASE_URL` を Production / Preview に登録。
4. **テスト**: `npm test`（祝日の単体テスト + サーバー起動中の API テスト。`BASE=https://<本番URL> node test/api.test.js` で本番にも実行可）

## 既知の制約

- 同期は最大3秒程度の遅れがあります（画面を閉じている間は同期しません）。
- 招待リンクは `?join=` のクエリで運ぶため、サーバーのアクセスログに残り得ます。参加は先着1人で、2人揃うと無効になります。
- ログイン試行の回数制限はありません（トークンが256bitなので推測は現実的ではありません）。
- 端末の保存データ（localStorage）が消えると、鍵が無くなって「すでに2人が参加しています」と表示されます。iPhone の Safari 系は、約7日触らないサイトの保存データを自動で消すためです。対策として、サーバーが発行する控えのクッキー（`futari_<カレンダーID>`、1年、アクセスのたびに更新）にも鍵を持たせ、保存データが無くてもそこから自動で復元します（認証そのものにはクッキーを使わず、`Authorization` ヘッダーのみ。クッキーだけでは 403）。クッキーも消えた場合は、設定の「自分用の復元リンク」を控えておけば戻れます。
